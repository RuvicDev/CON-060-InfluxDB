¿Qué es y para qué sirve?

El conector InfluxDB permite que el agente de Ruvic consulte datos de series de tiempo — ejecutar consultas Flux o InfluxQL, explorar qué buckets y measurements existen, y conocer el esquema de una measurement específica.

Una vez configurado, puedes pedirle al agente cosas como:

  • "¿Cuál fue la temperatura promedio de la última hora?"
  • "¿Qué measurements hay en el bucket de sensores?"
  • "¿Qué campos tiene la measurement de temperatura?"

Operaciones soportadas:

OperaciónQué hace
database.execute_queryEjecuta una consulta Flux o InfluxQL
database.list_buckets_or_measurementsLista los buckets del proyecto, o las measurements de un bucket
database.get_measurement_fieldsConsulta los campos y tags de una measurement
Conector de solo lectura Este conector no tiene ninguna operación de escritura — solo consulta datos ya almacenados.

Prerrequisitos

  • Un proyecto de InfluxDB (Cloud u OSS 2.x) accesible por red desde donde corre Ruvic.
  • Saber si el uso será principalmente en Flux (recomendado, InfluxDB 2.x) o InfluxQL (compatibilidad con 1.x).

Configuración en el fabricante

  1. Genera un API Token. En la interfaz de InfluxDB: Load Data → API Tokens → Generate API Token.
  2. Elige "Read" (no "Read/Write"). Acótalo a los buckets específicos que el agente necesita consultar, en vez de un token "All Access".
  3. Confirma la URL, organización, y bucket(s) por defecto. La URL varía según sea InfluxDB Cloud (ej. tu región AWS/GCP/Azure) u OSS auto-hospedado.

Permisos requeridos

El token necesita, como mínimo, permiso de lectura sobre los buckets que el agente vaya a consultar — no uses un token "All Access" si puedes acotarlo.

PermisoPara qué sirve
Lectura (Read) sobre los bucketsEjecutar consultas, listar buckets o mediciones y ver sus campos
EscrituraNo se requiere: el conector no tiene operaciones de escritura

Configuración en Ruvic

Entra a Settings → Conectores, busca la tarjeta InfluxDB y pulsa Configurar.

Completa la URL, token, y organización. Elige el lenguaje de consulta por defecto (Flux es lo recomendado salvo que necesites compatibilidad con InfluxDB 1.x).

Guarda y pulsa Probar conexión.

Verificación

  1. Test de conexión exitoso.

    El botón Probar conexión debe responder: "Conexión exitosa a [URL]".

  2. Prueba mínima con el agente.

    Pide algo de solo lectura primero:

    "¿Qué buckets hay disponibles?"

Solución de problemas

Mensaje / síntomaCausa probable y solución
"Permisos insuficientes"El token no tiene acceso de lectura al bucket consultado, o expiró/fue revocado.
"El modo InfluxQL requiere indicar 'bucket'..."En InfluxQL siempre hay que indicar el bucket (equivalente al "database" de InfluxDB 1.x) — configura uno por defecto, o indícalo en cada consulta.
get_measurement_fields falla en modo InfluxQLEsta operación solo funciona en modo Flux (usa el paquete de introspección de esquema de InfluxDB 2.x).

Preguntas frecuentes y notas de seguridad

¿El agente puede escribir datos en InfluxDB?

No. Este conector no tiene ninguna operación de escritura, ni siquiera con un flag de habilitación como otros conectores de la plataforma.

¿Dónde queda guardado el token?

Como secreto en el almacén de credenciales de la plataforma. La interfaz nunca vuelve a mostrarlo.

Buenas prácticas Usa un token de solo lectura, acotado a los buckets específicos que el agente necesita; y siempre acota tus consultas Flux con range() para no escanear todo el histórico sin necesidad.
